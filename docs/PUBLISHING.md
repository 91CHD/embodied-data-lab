## 两种分享方式

1. **GitHub 源码仓库**：访问者能看代码、README、截图、架构和测试，克隆后在自己的电脑运行。账号与登录方式确认后可以发布此版本。建议仓库名 `embodied-data-lab`。
2. **可操作的在线演示**：访问者打开网址即可回放预置数据、看报告和实验。需要托管前端、API、数据库和 worker，并单独验证部署；当前本机服务不是互联网演示。面向陌生访问者时，优先做预置样本的只读演示，保持稳定和可控的运行成本。

GitHub Pages 托管静态 HTML/CSS/JavaScript，可以承载项目介绍或纯前端展示。完整 FastAPI/PostgreSQL/worker 不会因为源码上传到仓库就自动运行。[GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

## 一个容易看懂的仓库首页

- 第一屏说明用户是谁、解决什么问题，配实际工作台截图。
- 给出一次短演示：轨迹回放 → 坏数据检查 → 下载报告 → 实验追溯。

- 清楚区分本地已经运行的测试、尚未执行的CI/容器验证、未来训练能力。
- 重点解释三个工程选择：共享分片时间映射、独立worker与租约、数据版本和产物追溯。

README 的数字是带日期的本地验收记录；上线后真正跑过 GitHub Actions，才能添加对应CI通过徽章。演示视频应录制真实页面操作，建议控制在60–90秒，配简短字幕说明业务过程。

## 开发者可以亲手做什么、学到什么

| 亲手完成的任务 | 能学到的知识 | 面试时可以展示 |
| --- | --- | --- |
| 在浏览器Network观察导入请求，然后沿代码找到数据库Job | HTTP/JSON、Pydantic、API分层、事务 | 解释“点击按钮之后发生了什么” |
| 增加一个数据来源筛选并贯通前后端 | Vue响应式、URL参数、SQL查询、分页 | 一次完整可演示的全栈修改 |
| 给坏样本增加一条检查规则，解释准确定位 | Python、Parquet、schema、边界条件、测试 | 自己发现并解决的数据问题 |
| 实现报告异常跳转episode与帧 | Vue Router、帧/时间映射、视频seek、图表联动 | 从业务问题到可用交互的设计 |
| 复现worker停止、重试和日志恢复 | 进程、PG行锁、租约、幂等、SSE | 为什么任务不会依赖浏览器存活，以及保证的边界 |
| 创建自己的分支、提交、PR，并跑CI | Git、变更说明、自动验证、代码审查 | 真实改动历史与验证证据 |

建议先挑一个小任务自己完成。每次保留：问题是什么、改了哪些文件、为什么选择此方案、验证结果，以及遇到过的错误。Agent可以协助，但需要自己能够解释和修改关键流程。
